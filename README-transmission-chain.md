# 開盤前訊號模組（v2）

整塊只回答一個問題：**台股開盤前，要不要調整部位？**

v1 的六節傳導鏈已經拿掉。實測近 60 日只有「費半→台股（隔夜）」和「油價→10年債」兩節有連動，
中間的美元、日圓幾乎是零。燈號又用固定水位，美元換到 101～102 的區間之後紅燈連亮一個多月，失去意義。

## 燈號怎麼決定

| 角色 | 項目 | 來源 |
|---|---|---|
| **決定燈號** | 台指期夜盤漲跌（抓得到時優先） | 期交所 OpenAPI |
| **決定燈號** | 費城半導體隔夜漲跌（夜盤抓不到時用） | yfinance / Stooq |
| 確認用 | 外資現貨買賣超（前一日、近 5 日累計） | 證交所 BFI82U |
| 背景 | 布蘭特 5 日、美10Y 單日、美元指數 5 日、美元/日圓 5 日、布蘭特−WTI 價差 | yfinance / Stooq |

門檻全部是 **z 分數**：今天的變動是「自己近 60 個交易日波動」的幾倍。

| z | 燈號 | 建議 |
|---|---|---|
| ≤ −2 | 強烈偏空 | 開盤不追價，考慮先減碼或避險 |
| ≤ −1 | 偏空 | 保守操作，新倉等盤中確認 |
| −1 ～ +1 | 中性 | 照原計畫 |
| ≥ +1 | 偏多 | 環境有利，可依計畫進場 |

外資與背景項目不改燈號，只在條件成立時於結論下方出現提醒（台股漲但外資大賣、外資 5 日累計賣超逾 500 億、背景項目 |z| ≥ 2.5）。

門檻在 `market_corr.py` 的 `CORE_Z`、`BG_Z`，要調自己改。

## 準不準：兩種驗證

1. **回測**：每次執行都用近兩年資料，把同一套規則套到過去每一天，算各燈號之後台股隔日的平均報酬與下跌機率。網頁上的表格就是這個。
2. **實戰紀錄**：`data/signal_log.csv` 每天記下當天燈號，台股收盤後自動回填實際漲跌。累積一兩個月後看它和回測是否一致。

右邊的折線是費半→台股 60 日滾動相關。掉到 0.3 以下代表連動變弱，這套規則暫時不可靠。

## 修掉的問題

- **台股晚一天**：Yahoo 的 `^TWII` 在早上排程時常缺前一天收盤，v1 面板顯示的台股其實是前天的。現在改用證交所官方資料（FMTQIK），Yahoo 只當備援。
- **週末／假日重複判讀**：沒有新資料時不重寫 JSON，排程也不會產生 commit。

## 檔案

| 檔案 | 做什麼 |
|---|---|
| `market_corr.py` | 抓資料、算訊號、回測、寫 `data/correlations.json` |
| `run_market_corr.bat` | 排程用，含自動 push（`AUTO_PUSH=1`） |
| `data/taiex_twse.csv` | 證交所加權指數快取（第一次抓 25 個月，之後只補最近兩個月） |
| `data/foreign_flow.csv` | 外資買賣超快取（最近 30 個交易日） |
| `data/signal_log.csv` | 每日燈號與事後結果 |

## 安裝與排程

```bat
pip install yfinance pandas numpy
python market_corr.py --offline-test --out data\test.json   :: 合成資料，確認流程
python market_corr.py                                        :: 真實資料（第一次約 1 分鐘，要抓證交所兩年資料）
```

Task Scheduler：每週二至週六 07:30 執行 `run_market_corr.bat`。
資料夾搬家後記得把排程的「動作」路徑改成新位置。
